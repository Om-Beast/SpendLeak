SSpendLeak SPENDING INTELLIGENCE

Last updated: 12 October 2026

Privacy Policy

This policy explains how SpendLeak handles information in its website and installed web app. SpendLeak is an independent project maintained at its public source repository.

Important: SpendLeak is a spending-pattern prototype, not a bank, fraud detector, accountant, or financial adviser. Until production storage, backups and operations are verified, use synthetic or redacted statements rather than real financial records.

Information you provide

  • Account information: display name and email address.
  • Authentication data: password hash and server-side session-token hash, not a readable password or raw session token.
  • Imported transaction data: dates, descriptions, merchant names, amounts, income/expense direction, categories, file name and an import fingerprint.
  • Preferences: display currency and in-app reminder preference.
  • Technical data: limited error logs used to diagnose failures. Do not put private financial data in public support reports.

How information is used

Imported data powers spending summaries, recurring-payment estimates, review flags and CSV export. These estimates can be wrong and are not proof of fraud or financial advice.

Optional AI explanations

AI explanations are requested only after a user presses “Explain my spending”. If Gemini is configured, the app sends aggregated totals, percentage changes, recurring/anomaly counts and application-approved category labels. It does not intentionally send raw transaction descriptions, exact transaction dates, account email or account ID in that request. If AI is unavailable or unconfigured, the app produces deterministic rule-based explanations instead. Provider processing is subject to Gemini API terms.

Storage and security

Passwords are hashed with scrypt. Session cookies use HttpOnly and SameSite=Strict; production cookies also use Secure. Mutating requests check origin, authenticated data routes are scoped to the current account, and SQL queries are parameterized. Local development can use SQLite; an explicitly applied production Blueprint uses managed PostgreSQL. The free demo deployment is not suitable for real bank statements, and the current app does not encrypt transaction records at application level or claim that every infrastructure backup is encrypted. No online service can guarantee absolute security.

Sharing

SpendLeak does not sell personal information. Hosting providers process app data. If the user explicitly requests a Gemini explanation and the integration is configured, aggregate metrics are sent to Google. The app does not request banking passwords, OTPs, or bank API access.

Retention and deletion

Information is retained while an account exists, subject to provider backup retention. Users can delete individual transactions, clear imported records, or permanently delete an account and associated active database records from Settings & privacy. The account-deletion page explains the web flow so deletion does not require reinstalling the app. Deletion from active storage may not immediately remove provider backup copies according to the provider's retention cycle.

Children

SpendLeak is not designed for children under 18 and does not knowingly target children.

Policy changes and contact

This page must be kept in sync with the deployed product and provider configuration. Before a public launch, the operator must verify each statement and complete Google Play Data safety disclosures accurately. For general issues use the GitHub issue tracker; do not post bank statements, passwords or transaction details there. Account deletion is self-service via the deletion page.
