# SpendLeak: zero-budget pilot and Android install guide

The goal of this configuration is to keep ongoing hosting and database bills at $0 while learning from a small number of real testers. This is a best-effort hobby pilot, **not a guarantee of production-grade uptime, backups, or security**.

## Free deployment architecture

- **Web/API:** Render Free web service, started from `render.free.yaml`. Its filesystem is ephemeral and it may spin down after inactivity, so the SQLite file must not be used for persistent user data.
- **Database:** Neon Free PostgreSQL. Create a Neon project on the free tier (currently advertised with up to 1 GB storage per project; quotas and terms can change). Copy its PostgreSQL connection string and set it as `DATABASE_URL` in Render's Environment page. Never commit the connection string.
- **AI:** Rule-based explanations work for free with no API key. Optional Gemini free-tier usage may be available but has quota limits, and Google's pricing page says free-tier content may be used to improve products. For real financial users, leave Gemini unset by default; only enable it after clearly disclosing the data flow and getting informed opt-in.
- **Android:** Install the HTTPS PWA from Chrome (menu → Install app / Add to Home screen). It costs nothing and gives an app-like home-screen experience. A Play Store listing is not free for a new developer account: Google currently charges a US$25 one-time registration fee. If strictly $0 is required and you do not already have a Play Console account, use the PWA first.

Official references: [Render free instance limits](https://render.com/docs/free), [Neon free tier update](https://neon.com/blog/neon-free-plan-1-gb-per-project), [Gemini API pricing and free-tier data usage](https://ai.google.dev/gemini-api/docs/pricing), [Google Play Console signup](https://support.google.com/googleplay/android-developer/answer/6112435).

## Free setup steps

1. Create a free Neon project and choose a region close to the Render service. Copy the pooled/standard connection string as directed by Neon, including the SSL settings supplied in its dashboard.
2. Merge/review this branch before creating the Render service so the `database-postgres.js` adapter exists on `main`.
3. In Render, create a Blueprint using this repository's `render.free.yaml`. It creates only a Free web service; it does not create a paid database.
4. In the new Render service's Environment settings, set `DATABASE_URL` to the connection string copied from Neon. `APP_SECRET` is generated by Render. Keep both secret values out of GitHub.
5. Deploy and test sign-up, sign-in/out, CSV import/export, duplicate import, preferences, AI/rule fallback, account deletion, and service-worker privacy. Verify records survive service restarts because they are stored in Neon, not in the Render filesystem.
6. Test Neon compute sleeping/wake-up, connection limits, and available backup/export options. Free database tiers may sleep, change limits, or change terms. Make periodic independent exports and test restoring them before inviting more people.
7. Use only synthetic or redacted statements until an independent reviewer has checked data isolation, auth, deletion and incident handling.

## What free hosting does NOT guarantee

- Render Free services can spin down after 15 minutes idle and may take around a minute to wake. The web filesystem is ephemeral, and monthly usage caps may suspend service.
- Neon Free has storage/compute limits and is not a paid SLA/backup plan. Watch current account usage and provider policy.
- This service's in-memory rate limiter is not shared across instances, and the app still needs email verification, secure password reset, monitoring, a support contact, and an independent security review for a broader public launch.
- Do not claim that real bank data is fully encrypted at application level. Verify infrastructure encryption and backup policies from the actual provider dashboards.
- A free Gemini API is not equivalent to a private on-device model. Never send raw bank statements, transaction descriptions, exact transaction dates, OTPs, bank credentials or account numbers to an AI provider.

## PWA and Play Store

The branch includes a web manifest, icons, privacy policy, terms and account deletion page. After the free service is deployed over HTTPS, test Chrome's install flow on Android. The service worker deliberately never caches `/api/*` responses.

If you later decide to pay the one-time Play Console fee (or already have an account), the remaining steps are to create a Trusted Web Activity bundle with Bubblewrap, choose the permanent application ID, securely sign the AAB, publish Digital Asset Links with the real Play app-signing SHA-256 fingerprint, fill out Play Data safety accurately, and pass internal/closed testing. For new Play submissions from 31 August 2026, target Android 16 / API 36 or higher. Newly created personal developer accounts may also have closed-testing prerequisites; check the current Play Console requirements before release.
